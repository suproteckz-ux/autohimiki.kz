# Ozon: подготовка импорта и ручная публикация

Работа ведётся внутри autohimiki.kz. До изменений были Product, Category,
ProductImage и Laravel CLI; Ozon-интеграции, mapping и таблицы связей не было.
Paloma, Kaspi, витрина, цены сайта, заказы и существующие синхронизации не изменены.

## Что готово и что ещё не подтверждено

Реализованы CLI, подготовка payload, изолированный API-адаптер, локальные связи,
отчёты и тесты с поддельными HTTP-ответами. Реальных запросов к Seller API не было.
`OZON_ENABLED=false` по умолчанию запрещает запросы экспорта и синхронизации.
Единственное исключение — безопасная проверка подключения ниже.

## Безопасная проверка подключения перед выкладкой

```bash
php artisan ozon:test-connection
```

Команда работает при `OZON_ENABLED=false`, без БД и миграций. Выполняет ровно
один read-only запрос `POST /v3/product/list` с `limit=1`, без пагинации,
повторов и переходов по redirect. Ничего не создаёт и не обновляет, не вызывает
import, stock/price API, category tree и не сохраняет mapping.
Вывод: `Ozon connection: OK`, `credentials missing`, `unauthorized` (401),
`forbidden` (403) или `API unavailable` (прочие ошибки/некорректный ответ).
API key, тело ответа и текст сетевого исключения не выводятся и не логируются.
Успешная проверка не включает интеграцию и не подтверждает готовность импорта.
Команда добавлена в `app/Console/Commands/OzonTestConnection.php`, тесты —
`tests/Feature/OzonConnectionTest.php`.

**Гарантированный сценарий создания именно черновика пока НЕ подтверждён.**
Официальная документация https://docs.ozon.ru/api/seller/ при проверке
23.09.2026 возвращала redirect loop. Используемый адаптер `/v3/product/import`
нужно сверить с текущим контрактом до разрешённого первого теста. Это обычный
асинхронный импорт, не доказанный draft API. Обязательные атрибуты, размеры,
вес и regulatory-значения не выдумываются: Ozon может отклонить payload целиком,
а не создать карточку для доработки. Task ID не означает, что карточка создана.
Нельзя включать отправку, считая один локальный статус гарантией черновика Ozon.

Положительный остаток при создании **не отправляется**. Он сохраняется как
`desired_quantity = max(0, Product.quantity)`; реальный stock sync разрешён только
после явного подтверждения ручной публикации. Это осознанное ограничение относительно
пожелания отправить остаток сразу: отправка положительного остатка не должна
открыть продажи до проверки человеком. Отсутствие stock-запроса само по себе не
гарантирует статус «не опубликован» в кабинете; это проверяется в первом тесте.

В локальной `.env` нет DB-параметров каталога, доступная по умолчанию БД не подключилась.
Поэтому фактические ID/slug «Очистители салона», количество реальных товаров и
внешняя доступность их изображений **не установлены**. Название `interior` в тестах —
только fixture, а не найденный slug. Миграция рабочей/production БД не запускалась.

## Mapping и локальное состояние

`ozon_category_mappings`: уникальный `local_category_id`,
`ozon_description_category_id`, `ozon_type_id`, `enabled`.
Название берётся из Category, не копируется и не устаревает в отдельной таблице.
Выборка использует точное совпадение category_id, без дочерних категорий.
Mapping задаётся вручную одной командой. **Загрузки дерева Ozon нет вообще**:
клиент разрешает только четыре конкретных endpoint; category tree и price API запрещены.

`ozon_product_links`: уникальные `local_product_id` и `offer_id`, Ozon ID, task ID,
статус, даты экспорта/контента/остатков, `last_error`. Дополнительно:
`desired_quantity`, `create_attempted_at`, `publication_confirmed_at`.

Статусы: `pending` — попытка импорта зафиксирована до HTTP;
`exported` — Ozon вернул task ID; `requires_manual_review` — получен product ID,
но публикация человеком ещё не подтверждена; `published` — оператор подтвердил
ручную публикацию; `error` — ошибка. `requires_manual_review` является локальным
запретом stock sync, а не утверждением о статусе карточки в Ozon.

## Защита цены и обработка ошибок

1. Любая существующая локальная связь исключает повторный импорт с ценой.
2. Если связи нет, выполняется точечный `/v3/product/list` по одному offer_id,
   с `visibility=ALL`, включая архивные товары. Найденный товар только связывается.
   Неполный/неожиданный ответ запрещает создание.
3. Перед HTTP сохраняется уникальная запись попытки. Конкурентный процесс не
   сможет повторно получить право импорта этого товара.
4. Цена передаётся только в единственном create-запросе. Даже при 429, 5xx,
   таймауте или падении процесса create автоматически не повторяется:
   Ozon import является upsert, повтор может изменить цену уже созданной карточки.
5. Stock-запрос вообще не содержит price. Метода обновления цены нет.

После неоднозначного импорта нельзя удалять связь ради повторного запуска:
сначала вручную сверить SKU/задачу в кабинете. Сохраняется исходный SKU; его смена
в Product блокирует операцию. Не создавать тот же SKU параллельно вручную или
другими интеграциями между проверкой существования и импортом. Не менять аккаунт
Ozon в этой же БД без отдельной сверки связей.

Для чтения и stock-запросов: timeout 30 секунд, до трёх попыток при connection error,
429 и 5xx, экспоненциальная задержка, числовой Retry-After до 30 секунд.
HTTP 2xx с ошибкой отдельного товара не считается успехом. Ошибки одного SKU
не прерывают категорию. API response bodies и исходные сетевые исключения не
записываются в отчёт/БД/логи; выводятся фиксированные диагностические коды.

## Данные товара

Источник — только Product и его images. SKU не изменяется. Название сохраняется,
кроме trim и ограничения длины 500. Цена — текущая Product.price, валюта KZT
по умолчанию, без пересчёта. Валюта должна совпадать с настройками кабинета.
VAT не угадывается, пустое значение блокирует реальную отправку.

Description — существующий текст плюс «Характеристики» из attributes:
словарь ключ/значение или элементы name/value. Не поддерживаемые вложенные данные
не превращаются в выдуманные значения. Текст передаётся как атрибут 4191;
его применимость нужно проверить в текущем контракте выбранного типа Ozon.
ТН ВЭД, сертификаты, страна и отсутствующие специальные атрибуты не добавляются.

main_image и ProductImage.path превращаются в HTTPS URL `APP_URL/storage/...`.
Внешние URL, включая Kaspi, исключаются. Нет скачивания картинок у поставщиков.
Главное фото первое, gallery добавляется в порядке sort_order, дубликаты удаляются.
Отсутствие фото/описания даёт предупреждение, отсутствие SKU/имени/положительной
цены — ошибку одного товара. Проверка доступности фото — отдельная read-only команда.

## Команды и порядок первого теста

Команды ниже — инструкция для последующего запуска. Production migration, export,
deploy, commit и push в рамках этой работы не выполнялись.

Найти фактическую категорию на подключённой БД, только чтение:

```sql
SELECT id, name, slug FROM categories WHERE name = 'Очистители салона';
```

После разрешённого применения миграции сохранить известную пару идентификаторов:

```bash
php artisan ozon:map-category <actual-slug> <description_category_id> <type_id> --enable
php artisan ozon:export-category --category=<actual-slug> --dry-run
php artisan ozon:check-images --category=<actual-slug> --sku=<SKU>
```

Dry-run не делает HTTP-запросов и не пишет БД. Работает без Ozon-таблиц, показывая
missing mapping. Отчёт содержит selected, ready, пропуски фото/описания/цены/mapping,
существующие локальные связи, new, failed. Ready означает готовность локальных данных,
а не гарантию принятия Ozon. Проверку удалённых дубликатов dry-run не делает.

После отдельного разрешения, сверки актуального API и настройки безопасного сценария:

```bash
php artisan ozon:export-category --category=<actual-slug> --sku=<SKU>
# Альтернатива: --limit=1
php artisan ozon:refresh-imports --sku=<SKU>
```

Экспорт печатает Created/imported (принятые задачи, не проверенные карточки),
requires manual review, content updated (0), stock updated (0), price sent for new
(принятые задачи), price skipped for existing, skipped, failed, SKU и причины.
Сетевой сбой после отправки может означать, что цена дошла, даже если счётчик
принятых задач равен нулю. Такая попытка сохраняется в связи и не повторяется.

Вручную проверить появление карточки, её статус, отсутствие продаж, SKU, фото,
описание/характеристики, цену. Остаток до публикации удерживается локально.
Если Ozon отверг неполный payload, это ошибка, а не успешный черновик.
Не выгружать следующие товары до подтверждения результата первого теста.
Затем отдельно разрешённые 3–5 товаров; после второй проверки — вся категория.
Полная команда без `--sku`/`--limit` сама не проверяет бизнес-подтверждение этапов.

После ручного заполнения обязательных полей и публикации:

```bash
php artisan ozon:confirm-published <SKU> --confirmed-in-cabinet
php artisan ozon:sync-stocks --category=<actual-slug> --sku=<SKU> --dry-run
php artisan ozon:sync-stocks --category=<actual-slug> --sku=<SKU>
```

Stock sync требует `OZON_WAREHOUSE_ID`; источник — актуальный Product.quantity,
включая ноль, отрицательные значения заменяются нулём. Команда подтверждения
меняет только локальный допуск, сама ничего не публикует на Ozon. Расписания нет.

## Данные перед первым реальным тестом

Нужны `OZON_CLIENT_ID`, `OZON_API_KEY` (внести в защищённую `.env`, не присылать
в открытом сообщении), конкретная пара category/type для «Очистители салона».
Полное дерево категорий не требуется. Нужны также подтверждённые настройки
аккаунта VAT/валюты, а для последующего stock sync — warehouse ID;
их нельзя вывести из SKU или безопасно придумать. Требуется доступ к реальному
локальному каталогу для определения ID/slug. Сначала проверить API-контракт
и возможность неполной карточки, затем отдельно разрешить один SKU.

## Проверки

```bash
php vendor/bin/phpunit tests/Feature/OzonExportTest.php
```

Тесты запускают только перечисленные миграции в SQLite `:memory:`; не подключаются
к production и не делают реальных HTTP-запросов. Проверяются категория/активность,
SKU, фото/галерея, description+attributes, mapping, цена только при создании,
удалённые дубликаты, неопределённый результат импорта, retry, нулевые/отрицательные
остатки, запрет stock до подтверждения, per-item ошибки, dry-run, секреты и allow-list API.
Content sync отсутствует; проверяется, что повторный export изменённого контента
не отправляет ни контент, ни цену.
